# TokenMoon 指标口径

本文说明 TokenMoon 桌面端对请求、用量、等效费用及吞吐量的统计口径。

| 指标 | 口径 |
| --- | --- |
| 请求数 | 一条归并后的请求算一次。没有 HTTP 状态的会话日志仍然计入；明确失败的行也计入请求总数。 |
| Token | 用量合计为未缓存输入 + 缓存读取 + 缓存写入 + 输出。请求表的「输出 Tokens」列显示输出，并用较小的数字标出其中的推理 Token。推理已包含在输出中，5 分钟和 1 小时缓存写入已包含在缓存写入中。 |
| 缓存命中率 | 所选请求的缓存读取总和 ÷（未缓存输入 + 缓存读取 + 缓存写入）的总和。分母为 0 时未知。 |
| 完整请求 TPS（兼容统计） | 单条 = 输出 Token × 1000 ÷ 完整请求耗时（毫秒），包含首 Token 前等待。只使用非失败、输出为正且有完整耗时证据的请求。时间分桶和会话取符合条件的逐条算术平均，缺样本时未知。此字段用于导入和同步兼容，桌面界面不展示该指标。 |
| 估算 TPS | 对未失败且输出为正的请求，优先用同一请求的日志时间差；日志间隔须大于零且小于 2 小时，速率不超过 10,000 tok/s。CPA 请求缺少可用日志时，可用已测完整耗时补位。汇总使用耗时至少 1 秒的样本，用合计输出除以合计所用秒数。观测台可切换全部有效样本与输出严格大于 800 Token 的样本；浮窗、会话等其他汇总继续纳入输出至少 1,000 Token 的样本。仅使用日志的结果显示 `≥`；缺样本时留空。 |
| 等效费用 | 以 USD 表示，只合计已计价的请求。缺价请求仍计入用量和请求数，未计价数量单独说明；仅有缺价请求时费用显示为未知。价格不代表订阅实付。 |

观测台的「近 24 小时」是从当前时刻往前推实际 24 小时，不在午夜归零；菜单栏和浮窗默认采用相同口径。浮窗小柱同样覆盖近 24 小时，按显示时区每小时分桶并裁剪首尾；点击某柱可查看该时段。菜单栏可选的趋势把同一个滚动 24 小时窗口等分成六个 4 小时桶。观测台按时间跨度和图表可用宽度自动分桶，从 1 小时、2 小时、3 小时、6 小时、12 小时和日／周／月等常见粒度中选取合适间隔；常规宽度的近 7 天通常用 6 小时。首尾桶裁到所选范围，近 7／30／90 天最后一桶截至现在。桶边界按所选显示时区，周从星期一开始。「全部时间」使用账本首尾请求之间的跨度。自定义范围可选起止日期及小时，含结束小时，实际用量统计截止到下一个本地时间边界之前。夏令时回拨时重复的小时分别列出，跳过不存在的小时。显示时区只影响界面与统计边界，不改写原始时间戳、WebDAV UTC 月分片或价目明确指定的计费时区。模型、设备、智能体、请求档位的选项来自当前时间范围，不受其他筛选影响；已经勾选的值保留到明确清除。每组支持多选，组内取并集、组间取交集。CPA 请求保留网关设备和来源，智能体按最终供应商或已转发模型归类。会话按设备、客户端和源会话 ID 分组，同一个会话的多个模型请求不会折算成一次。会话列表里的数字沿用当前时间和维度筛选。

`≥` 沿用 [Magpie 的会话日志估算标记](https://github.com/yetone/magpie/blob/v0.1.3598/internal/usage/ledger.go#L978-L1026)。日志间隔可能包含等待与客户端处理时间，无法用于得出精确的请求耗时或模型生成速度。完整耗时和日志间隔独立保存。精确模式缺少实测耗时时留空，不使用日志估算填补。

等效价格与原面板对齐需选择**同一份**价目及倍率。TokenMoon 初始选内置的公开价格快照，原面板默认选 OMC；两者均可切换。公开目录按 OpenAI、Anthropic、Google 的直营模型精确 ID 读取，不造别名；也支持导入面板使用的 `{"prices":[...]}` 公共价目。OMC 使用 `{"model_prices":[...]}`，包含 OMC 自身的价格倍率以及上下文和时段费率。模型匹配先查请求模型，再查实际模型。总输入（含缓存）用于选择上下文费率，精确阈值优先；时段按价目所给时区判定。模型无价目时，请求不计价，即使 Token 数为零。已有价目的模型仅要求非零 Token 桶有费率。`codex-auto-review` 参与用量但单独排除在价格覆盖率之外。

等效金额先将基础金额四舍五入到 USD nanos，再应用 Fast 或 UltraFast 的独立估价倍率，四舍五入到 USD nanos 后汇总。桌面端展示和筛选的是请求档位，计价仍读取实际返回等级：实际返回的 Fast/UltraFast 分别用对应倍率，实际返回 Standard/Flex/Scale 时保留基础价；缺少具体返回等级时才用请求档位作为估价依据。实际等级字段不会因此变成已确认值。Fast 默认 2.5 倍；UltraFast 没有沿用 Fast 的默认值，默认 1 倍，可在设置中独立调整。

「账号」筛选使用请求账号，邮箱不区分大小写并在界面脱敏。会话创建者不参与匹配；没有请求账号的记录归入「账号未记录」。已知使用 API Key 的记录不会并入同名邮箱。观测台默认排除各来源已识别的 API Key 请求；证据来自请求的登录方式、脱敏 API Key 或与请求关联的认证轨迹。认证方式缺失或冲突时保留该请求。CPA 的入站客户端 Key 标签与上游请求账号独立，OAuth 请求不因此被排除。

Fast 可以按渠道单独覆盖；未设置渠道倍率时沿用全局 Fast 倍率。公共价目可选 `cache_write_1h`，OMC 可选 `cache_write_1h_price_per_1m`，单位都是 USD／百万 Token。仅在请求报告的 1 小时缓存写入拆分与写入总量一致、且适用价目明确给出该费率时分开计价；否则沿用通用缓存写入费率并单独计数，金额仍计入已计价合计。只覆盖通用写入费率的上下文或时段档不借用基础价目的 1 小时费率。没有扩展字段或渠道覆盖的旧价目仍按原口径计价。
